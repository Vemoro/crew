# Hinweise für Coding-Agenten

Die Projektregeln stehen in [Entwicklung](docs/entwicklung.md), die Beitragswege in [Mitwirken](CONTRIBUTING.md), die Produktgrenzen und Board-Zustände auf der [Roadmap](docs/roadmap.md). Für Änderungen an der Oberfläche gilt [Crew-Gestaltung](DESIGN.md).

Prüfe Auftrag und Zielbasis vor der Arbeit. Schütze fremde Änderungen und nutze eine getrennte Testumgebung mit synthetischen Daten. Halte offene fachliche Entscheidungen fest. Veröffentliche Issues, PRs und Kommentare im vereinbarten Auftrag. Merge und Release brauchen die Freigabe des Maintainers.

| Aufgabe | Skill |
| --- | --- |
| Issues schreiben und zum Review übergeben | [crew-issue-schreiben](.agents/skills/crew-issue-schreiben/SKILL.md) |
| Problem, Lösungswahl und Abnahme eines Issues unabhängig prüfen | [crew-issue-pruefen](.agents/skills/crew-issue-pruefen/SKILL.md) |
| Roadmap prüfen und Karten pflegen | [crew-board-pflegen](.agents/skills/crew-board-pflegen/SKILL.md) |
| PR vorbereiten und einreichen | [crew-beitrag](.agents/skills/crew-beitrag/SKILL.md) |
| Selbstprüfung und fachliche Beitragsprüfung | [crew-beitrag-pruefen](.agents/skills/crew-beitrag-pruefen/SKILL.md) |
| Unabhängiges Code-Review | [crew-tdd-review](.agents/skills/crew-tdd-review/SKILL.md) |
| Unabhängiges Doku-Review | [crew-doku-pruefen](.agents/skills/crew-doku-pruefen/SKILL.md) |
| Lokale Prüfungen isoliert ausführen | [crew-checks](.agents/skills/crew-checks/SKILL.md) |
| Vorher-Nachher-Aufnahmen vor der ersten UI-Änderung vorbereiten | [crew-pr-screenshots](.agents/skills/crew-pr-screenshots/SKILL.md) |
| Offene und gestapelte PRs zur Entscheidung aufbereiten | [crew-prs-pruefen](.agents/skills/crew-prs-pruefen/SKILL.md) |

Die [Übernahme aus Desk](docs/desk-uebernahme.md) dokumentiert die Herkunft der Regeln.
